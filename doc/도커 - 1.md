# 1. Docker의 본질 (왜 쓰는가)

Docker는 한 줄로 말하면:

> **“애플리케이션 + 실행환경을 통째로 패키징해서 어디서든 동일하게 실행시키는 기술”**

### 해결하는 문제

* “내 컴퓨터에선 되는데?” 문제
* 서버 환경 차이 (Node 버전, OS, 라이브러리 등)
* 배포 복잡도 증가

---

# 2. 핵심 개념 4개 (이건 무조건 이해해야 함)

## 1) Image

* 실행에 필요한 모든 것을 포함한 **설계도**
* 읽기 전용 (immutable)
* 예: Node, Nginx, MySQL 이미지

👉 비유: “앱 설치 파일”

---

## 2) Container

* Image를 실행한 **실제 프로세스**
* 독립된 환경에서 실행됨

👉 비유: “설치된 앱 + 실행 중 상태”

---

## 3) Dockerfile

* Image를 만드는 **설정 파일**
* 코드처럼 관리됨

예:

```dockerfile
FROM node:18
WORKDIR /app
COPY . .
RUN npm install
CMD ["npm", "start"]
```

👉 “이렇게 이미지 만들어줘”라는 레시피

---

## 4) Registry

* 이미지를 저장하는 저장소
* 대표: Docker Hub

---

# 3. 동작 구조 (중요)

Docker는 내부적으로 이렇게 돌아감:

```
[Docker CLI] → [Docker Daemon] → [Container 실행]
```

### 핵심 포인트

* Docker는 사실 **VM이 아님**
* OS 커널을 공유함
* 격리는 namespace + cgroup으로 처리

👉 그래서 가볍고 빠름

---

# 4. VM vs Docker 차이 (자주 물어봄)

| 항목 | VM    | Docker   |
| -- | ----- | -------- |
| OS | 각각 있음 | 공유       |
| 속도 | 느림    | 빠름       |
| 용량 | 큼     | 작음       |
| 격리 | 강함    | 상대적으로 약함 |

👉 Docker는 “프로세스 격리 기술”

---

# 5. Docker 기본 명령 흐름

## 1) 이미지 가져오기

```bash
docker pull nginx
```

## 2) 컨테이너 실행

```bash
docker run -d -p 80:80 nginx
```

## 3) 상태 확인

```bash
docker ps
```

## 4) 종료

```bash
docker stop <container_id>
```

---

# 6. 볼륨 (데이터 유지 핵심)

Docker는 기본적으로:

> 컨테이너 삭제 = 데이터 삭제

그래서 사용하는 게 Volume

```bash
docker run -v /host:/container
```

### 왜 필요?

* DB 데이터 유지
* 로그 저장
* 파일 공유

---

# 7. 네트워크

컨테이너끼리 통신할 때 필요

### 기본 네트워크

* bridge (기본)
* host
* none

### 예시

```bash
docker network create my-network
```

---

# 8. Docker Compose (실무 핵심)

여러 컨테이너를 한 번에 관리

예:

```yaml
version: "3"
services:
  app:
    build: .
    ports:
      - "3000:3000"
  db:
    image: mysql
```

```bash
docker-compose up
```

👉 백엔드 + DB 같이 띄울 때 필수

---

# 9. 이미지 레이어 구조 (중요 개념)

Docker Image는 레이어 구조:

```
node:18
  + npm install
  + copy source
```

👉 변경된 부분만 새로 생성됨
👉 캐싱으로 빌드 속도 빨라짐

# 10. 실무에서 중요한 포인트

## 2) .dockerignore

* node_modules 제외 필수

## 3) 환경변수 관리

```bash
ENV NODE_ENV=production
```

## 4) 보안

* root 사용자 사용 금지

# 12. 개발자 관점 핵심 정리

* Docker는 **배포 도구이면서 개발 환경 통일 도구**
* “컨테이너 = 하나의 서버”라고 생각하면 편함
* Compose는 “로컬 쿠버네티스 느낌”
